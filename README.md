Routing Optimization Service (Master Schedule)
Даний проєкт призначений для автоматичної генерації оптимального розкладу техніків на основі вхідних даних з Excel-таблиці на основі алгоритмів Google OR-Tools для розв'язання задачі маршрутизації транспортних засобів з урахуванням навичок техніків, часових вікон локацій та синхронізації кількох працівників на одну локацію.

Попередні вимоги
- .NET 10.0 SDK;

- AWS Account: Для роботи GeocodingService необхідно мати підключення до Amazon Console (проєкт використовує AWS Location Service для перетворення адрес у координати);

- AWS Lambda Test Tool: Для локального тестування.

Вхідні параметри
Проєкт працює за принципом обробки файлів Excel, розташованих у локальній директорії OBG/input/ (її потрібно створити).

У корені проєкту знаходиться папка config, у ній знаходиться файл routing-planning-config.json, де можна прописати на скільки днів будуть генеруватися маршрути

Формат даних: Система очікує два основних листки у таблиці з відповідними колонками, за назвами яких йде пошук:

Service sites: 
- Location name (Назва локації);
- Site address (Адреса локації);
- Current technician (Поточний технік за навяності);
- Site best accessed (Як краще діставатися до локації, наприклад car/van);
- How many techs needed (Кільість необхідних техніків

Допуски та дозволи:
- Permit required (Чи потрібен допуск на локацію, Yes/No, замість No може бути порожня клітинка);
- How difficult (Складність отримання доупску, Easy, Medium, Hard);
- Techs with permit (Список техніків, у яких уже є допуск)
- Вікна доступу (Mon, Tue, Wed, Thu, Fri): Пари колонок From та To для кожного дня тижня;
- Visit freqency (Частота візитів, наприклад 3x a week або 1x in 14 days);
- Est duration (Тривалість візиту у хв);
- Service skill requirement (Необхідна кваліфікація, наприклад exterior - medior);

Matchmaking (Пріоритети):
- Should be serviced by: Бажані техніки (Preferred);
- Should not be serviced: Небажані техніки (Prohibited);

Логічні вимоги до техніка (Yes/No, замість No може бути порожня клітинка):
- Physically demanding (Спроможність до важкої фізичної праці);
- Living walls (Навички роботи з живими стінами);
- Work at heights (Допуск до роботи на висоті);
- Lift (Сертифікат на використання підйомника);
- Pesticide (Сертифікат на роботу з пестицидами);
- Citizen (Наявність громадянства);

Technicians:
- Name (Ім'я техніка);
- Home address (Домашня адреса);
- Office address (Адреса офісу);
- Starts from (Початок маршруту, очікується: home або office);
- Finishes at (Кінець маршруту, очікується: home або office);
- Робочі години (Mon, Tue, Wed, Thu, Fri): Пари колонок From та To для кожного дня тижня;
- Min break (Мінімальний час перерви у хв);
- Break should be taken not earlier (Перерва має бути не раніше ніж, HH:mm);
- Break should be taken not later (Перерва має бути не пізніше ніж, HH:mm);
- Maximum hours of work per day (Максимум робочих годин на день, число);
- Maximum hours of work per week: (Максимум робочих годин на тиждень, число);
- Service skills (Навички): Список через кому у форматі тип - рівень (interior - medior, floral - junior);
- Target days for schedule: Дати, на які потрібно побудувати розклад (для усіх техніків), dd.MM.yyyy.

Логічні параметри (Yes/No, замість No може бути порожня клітинка):
- Physically demanding (Спроможність до важкої фізичної праці);
- Living walls (Навички роботи з живими стінами);
- Work at heights (Допуск до роботи на висоті);
- Lift (Сертифікат на використання підйомника);
- Pesticide (Сертифікат на роботу з пестицидами);
- Citizen (Наявність громадянства);

Запуск проєкту
1. Розмістіть вхідний Excel-файл у папці OBG/input/ (створіть її).

2. Відкрийте проєкт OBG/ObgLambda у вашій IDE

3. Запустіть проєкт (наприклад, через Visual Studio або dotnet run). Відкриється браузер із Mock Lambda Test Tool на localhost.

4. Для виконання на сторінці Test Tool натисніть кнопку Execute Function. Доведется трохи почекати в залежності від об'єму роботи.

Інтерпретація результатів
Після успішного виконання ви отримаєте два види результатів:

1. Логи консолі у вікні Log Output:
- Логи типу [MASTER][MISS] вказують на локації, які були пропущені через певні обставини, missedVisits показує скільки з необхідних візитів було пропущено;
- PlacementSummary показує скільки візитів було розподілено з необхідної їх кількості;
- На кожен день циклу виводиться кількість візитів. Також виводяться витрати часу у хвилинах у порівнянні з максимальними спроможностями команди;
- [EXPORT] вказує, куди було записано JSON зі створеним майстер-календарем;
- [CONFIG] вказує, на скільки днів будуть плануватися маршрути, а також на місцезнаходження файлу конфігурації;
- [PLAN] уточнює довжину інтервалу в днях, а також кількість днів для розрахунку маршрутів
- [DAY] уточнює, на який саме день створюються маршрути, кількість локацій у цей день. А також, за умови знаходження рішення, активних техніків, кількість їхніх зупинок та загальну кількість витрачених годин;
- [EXPORT] вказує, куди було записано JSON зі створеним output;
- [DONE] вказує на успішне виконання команди.

2. Фінальні JSON з майстер-рокзкладом (master-calendar) та побудованими маршрутами на конкретний день (output).
master-calendar.json має наступну структуру:
- CycleStartDate: дата початку циклу (з понеділка);
- HorizonDays: горизонт планування, максимальний інтервал між візитами;
- Days: дні цього інтервалу;
- Day: 1-based нумерація днів;
- Date: дата цього дня;
- Services: локації на цей день, які необхідно відвідати;
- SiteId та SiteName: Id та назва локації;

output.json має наступну структуру:
- scheduleStartDate: початковий день для планування маршрутів;
- horizonDays: горизонт планування, максимальний інтервал між візитами;
- technicianDirectory: список доступних техніків;
- techId та name:  Id та ім'я техніка;
- serviceDirectory: список необхідних локацій для візитів;
- serviceId та name:  Id та назва локації;
- weeks: підсумки по конкретному тижню;
- weekStartDate та weekEndDate: дати початку та кінця тижня (пн-нд);
- technicianWeekSummary: підбиття підсумків для техніків за тиждень;
- techId: Id техніка;
- workedMinutes та workedHours: витрачені хвилини та години роботи;
- days: розклад на конкретний день;
- day: дата цього дня;
- routes: список маршрутів по технікам;
- techId: Id техніка;
- stops: список зупинок техніка;
- type: тип зупунки: start для точки початку, service для обслуговування локацій, break для перерви, end_point для точки завершення;
- arrivalTime: час прибуття у точку;
- durationMinutes: витрачений час на точці;
- address: адреса точки;
- serviceId: Id локації за наявності;
